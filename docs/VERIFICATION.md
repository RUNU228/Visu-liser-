## Performance and long run

Final timing and ownership records: `docs/verification/performance-chrome.json` and `soak.json`. The 60-second default active-page run reports latest-sample latency median/p95/max, FFT-center age separately, median FPS, render-duration p95, explicit analysis reservation, retained history, Canvas backing-store bytes, browser heap and device audio latency. The latest-sample p95 target is ≤150 ms. Browser decoder memory and Canvas memory are not claimed inside the 64 MiB application analysis reservation.

The final isolated 60-second run measured **59.88 median FPS**, **8.6 ms p95 rendering**, and latest-sample latency **18.69 / 26.69 / 53.35 ms median / p95 / maximum**. FFT-center age p95 was 69.34 ms. Primary capture stayed running. Two initial/discontinuity boundaries were recorded. Explicit conservative analysis reservation, including renderer typed scratch, was **25,352,432 bytes (24.18 MiB)**; retained history was 2,715,776 bytes. Main and offscreen Canvas backing stores were separately 14,014,960 and 2,360,416 bytes. Browser heap used 48,208,886 bytes; reported base/output latency was 10/40 ms.

The ten-minute run uses an eleven-minute MP3, followed by 20 distinct queue track switches. It samples capture state, reserved/history bytes, heap and live URL ownership each minute. Clear is followed by the five-second Undo expiry and a GC request; queue and importer URLs must both reach zero. Temporary heap fluctuations are not classified as leaks. Physical listening, browser-internal decoder allocations and operating-system handles are not measured by these counters.

The completed 600-second run retained capture at all eleven samples, with one queue-owned URL, fixed reservation **17,569,280 bytes (16.76 MiB)** and retained history **1.63–2.58 MiB**. This soak preceded the final renderer optimization and conservative renderer-scratch reservation audit; its reservation is historical, while the final 24.18 MiB reservation above covers those caches. Twenty switches kept that same historical reservation; Clear/Undo expiry left zero queue rows, URLs, stereo points and retained history, with no page errors. Heap samples during continuous playback ranged **23.97–54.84 MiB**. The immediate post-switch heap was transiently 131.85 MiB.

The final separate twenty-import/switch ownership run used Chromium's explicit heap collection and measured **114.98 MiB peak → 5.75 MiB cleared**. Backing storage was 7.46 MiB after Clear, including reusable application scratch; scheduler/controller teardown reduced it to 4.50 MiB. All queue/Undo/URL/history owners were released. These measurements include the final renderer, lazy spectral lookup allocation and explicit renderer scratch teardown. Evidence is retained in `ownership-cleanup.json` and reproduced with `node scripts/cleanup.mjs`.

Other browser/DSP verification ran concurrently with parts of the ten-minute run. Seventy analysis discontinuities accumulated during that load, including the initial session boundary; twenty-one further boundaries came from switching/clearing. This is recorded as a loaded analysis stress run, not a dropout-free isolated latency run. Stale PCM is discarded and its gap marked; the worklet's audible passthrough does not depend on analysis pool credits. Physical audible dropout absence was not measured. Final default performance is measured separately without concurrent test browsers.
